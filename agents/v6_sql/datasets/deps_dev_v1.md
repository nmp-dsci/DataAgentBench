- Repo metrics (stars, forks, open issues) exist ONLY as free text in `deps_dev_v1_project_info."Project_Information"`. Take the `owner/repo` slug as the first slash-joined token (regex like `[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]*[A-Za-z0-9_-]`), lowercase it, and join it to lowercased `deps_dev_v1_project_packageversion."ProjectName"`. Don't LIKE-match the whole text.
- Numbers can have thousands commas (54 rows). Strip them, then cast to bigint.
- Forks come in 3 phrasings that don't overlap and together cover all 770 rows: "forks count of N" (154), "forked N times" (68), "N forks" (548). Use coalesce over all three, case-insensitive.
- Stars: "stars count of N" (170), "N stars" (599), plus one row phrased "starred by N users". Use all three.
- Open issues: "open issues count of N" or "N open issues".
- `Licenses` (project and package) and `VersionInfo` are JSON stored as text. Parse them as jsonb (key-exists test for 'MIT'; read the IsRelease and Ordinal keys as text, then cast) instead of LIKE. "Project license" means `project_info."Licenses"`.
- Join path: packageinfo(System,Name,Version) = project_packageversion(System,Name,Version), then ProjectName = slug.
- IMPORTANT, output shape: one project maps to many package versions. Any question that ranks or lists projects/packages after filtering on package attributes (System, IsRelease, etc.) must also return a Version column. Pick exactly one qualifying row per project with row_number(): newest `UpstreamPublishedAt` first (nulls last), then the highest integer Ordinal from VersionInfo, then `Version` text descending. Output `ProjectName` (in its original case from project_packageversion), that `Version`, and the metric (e.g. forks). Returning only DISTINCT project names plus the metric counts as wrong, even though the question only says "which projects".
