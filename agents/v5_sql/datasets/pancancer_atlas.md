- When a question says "histological type"/"histology type" as a plain English phrase, use the free-text `histological_type` column (e.g. "Infiltrating Ductal Carcinoma"), NOT the coded `icd_o_3_histology` field (e.g. "8500/3") — the two are many-to-many (one text label maps to several codes and vice versa, verified on Breast invasive carcinoma rows), so grouping by the wrong one changes every downstream count/statistic. Only use `icd_o_3_histology` if the question explicitly asks for the ICD-O-3 code.
- Both `histological_type` and `icd_o_3_histology` (and other coded clinical columns) can hold bracketed sentinel values like `[Not Available]`; "known"/"valid"/non-bracketed histology means excluding rows where the column IS NULL OR matches `^\[.*\]$` — check whichever of the two columns the question actually names.
- Extract patient sex from `Patient_description` with a word-boundary regex (`\m(MALE|FEMALE)\M` or similar), never `ILIKE '%FEMALE%'`/`'%MALE%'` substring matching — "FEMALE" contains "MALE" as a substring, so plain substring checks on MALE will also match FEMALE rows and inflate/corrupt sex-based filters.
- For chi-square questions, build the full row x column grid (cross join of all kept categories) so empty cells contribute o=0, drop rows/columns whose marginal (summed) total is <= (or below, per the question's wording) the given cutoff using each cell's own row/column marginal — not a pre-filtered subset — then compute Σ(O-E)²/E over the surviving cells with E = row_total*col_total/grand_total computed from the same kept grid.
