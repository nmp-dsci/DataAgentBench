- Join key: yelp_business.business_id is "businessid_N"; yelp_review.business_ref / yelp_tip.business_ref is "businessref_N". Join by turning one prefix into the other and comparing full strings, not by extracting only trailing digits from each side with a regex — that numeric-only approach can match rows differently and shifts which reviews get pooled per group.
- State extraction from yelp_business.description: the state is the two-uppercase-letter token right after "<City>, " — but the character right after the state code is NOT always a comma (one description reads "...Philadelphia, PA location offers..." with no comma after PA). Use a word-boundary regex on the two letters, not a pattern requiring a trailing comma, or you drop/misclassify rows.
- Categories in description: text after the "<City>, <ST>," clause holds capitalized category phrase(s) joined by space, "&", "/", "of", or parenthetical qualifiers like "(New)"; extract the whole run of such phrases in order, listing every category found, not just the first substring after the location clause.
- Date range filters on yelp_review.date/yelp_tip.date (after parsing to timestamp): an inclusive end date means keeping timestamps up to but not including the start of the next day; an upper bound of exactly midnight on the end date excludes real rows timestamped later that same day (confirmed such rows exist).
- "Highest number of X" / top-1 rankings need a deterministic tie-break (secondary count/id ascending) before limiting to one row.
- Return only the columns the question asks for; don't leave extra helper columns (e.g. a raw count) in the final result.
- For "U.S. state" questions, filter the extracted 2-letter code against the 50 states + DC; non-US codes (e.g. Canadian province abbreviations) appear in the description text and must be excluded.
