- Join key: yelp_business.business_id is "businessid_N"; yelp_review.business_ref / yelp_tip.business_ref is "businessref_N". Swap one prefix for the other and compare the full strings.
- Every yelp_business.description begins "Located at <address> in <City>, <ST>, this ..." and names the state as a two-letter code. One row has no comma after the state ("Philadelphia, PA location ..."), so match the code with a word boundary (`\M`), not a trailing comma. For "U.S. state" questions, keep only the 50 states + DC, because non-US codes also appear.
- Categories are not stored in their own column. They are the list of Capitalized phrases in the description after the "City, ST," clause. The wording before the list varies: "services in", "including", "featuring", "seeking", "in the category of", "fields of" and others. Some lists end the sentence and some are followed by lowercase text (", perfect for...", " cuisine", " options for..."), so no single "featuring ... , perfect" style pattern works (only 3 of 100 rows fit that one). A category is a capitalized phrase: capitalized words joined by space, " & ", "/", " of ", plus parenthetical qualifiers like "(New)" or "(Traditional)". Take every such phrase with a global regex, in order. Drop list glue ("and") and lowercase words, and join the phrases with ', '. When a question asks for a business's category, return all of its categories, not one substring.
- yelp_review.date is text in exactly 3 shapes, which cover all 2,000 rows: 'YYYY-MM-DD HH24:MI:SS', 'D Mon YYYY, HH24:MI' (1–2 digit day), 'Month D, YYYY at HH12:MI AM'. Detect each shape with a full anchored regex and parse it with the matching format.
- Date windows: reviews have times later in the day, so an inclusive end date means < the next day's midnight.
- Top-1 rankings need a deterministic tie-break (e.g. count desc, then id) before limiting to one row. Return only the columns asked for.
