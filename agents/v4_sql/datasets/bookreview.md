- Output formatting (applies to ANY question whose answer is book titles, however phrased — "list the titles", "which books...", "return all matching books", etc., not only questions literally saying "list titles"): gold answers always CSV-encode the title column — if a title contains a comma, wrap the whole title in double quotes and double any internal double quotes (standard CSV field quoting). ~34/200 titles in bookreview_books_info contain a comma. Always apply this transform to any returned title column before submitting, even in pass_through mode; do not return the raw title text when the question's answer is a list of book titles.
- Join key: `books_info.book_id` is `bookid_N`, `review.purchase_id` is `purchaseid_N`. Join by extracting the trailing integer from each side (`substring(... from '[0-9]+$')::int`) and comparing as integers, not by concatenating a prefix or using LIKE/wildcard on ids.
- `categories` is a string-encoded list, e.g. `["Books", "Literature & Fiction", "Poetry"]`. Match a category by its exact quoted element (regex on `"CategoryName"`), not a loose `LIKE '%CategoryName%'`, since category names can be substrings of each other and of surrounding text.
- Book language lives only in the templated `details` text, with many phrasings ("written in English", "available in English", "is in English", "this English-language ...", bilingual "available in both English and X"). Use a word-bounded regex (`\mEnglish\M`) on the language name so all phrasings match while avoiding partial-word false matches; bilingual English editions still count as English.
- `review_time` is text in one consistent date-time format across all rows (1997-2023); cast directly with `::timestamp`.
- Compute average rating per book by grouping individual `bookreview_review` rows (joined via the extracted id) and taking `avg(rating)`; never use any pre-aggregated rating field on `books_info`.
