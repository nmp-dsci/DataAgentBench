- Join key: business_id values look like "businessid_N" in yelp_business; business_ref values look like "businessref_N" in yelp_review/yelp_tip, same N. Join by matching the numeric suffix after stripping each prefix, not raw string comparison.
- State: yelp_business.description always has "..., <City>, <ST>," (two-letter uppercase state) after the city. Use a word-boundary regex so trailing punctuation isn't captured. Some codes are non-US (e.g. Canadian provinces); for "U.S. state" questions, filter against the 50 US codes + DC.
- Categories aren't a column. description = "<varying lead-in: Located at/Situated at/Located in/This vibrant spot at/This <city>,<ST> location> ... <City>, <ST>, <descriptor> offers ... <category>, <category>...". Lead-in wording varies across rows. To get categories, take the text after "<City>, <ST>," and pull capitalized phrase(s) joined by ", "/" & "/"/"/" of "/parenthetical qualifiers. Don't anchor on one fixed lead-in or ending phrase; it only covers some rows.
- yelp_review.date/yelp_tip.date mix three text formats in one column: 'YYYY-MM-DD HH24:MI:SS', 'DD Mon YYYY, HH24:MI', 'Month DD, YYYY at HH12:MI AM'. Detect each row's shape and parse with the matching to_timestamp format; one LIKE/regex alone misses rows in other shapes.
- "Average rating of businesses in <group>" means pool all matching reviews into one AVG, not average of per-business averages.
- Break ties in "highest/most" with a secondary sort key, not arbitrary LIMIT 1 order.
