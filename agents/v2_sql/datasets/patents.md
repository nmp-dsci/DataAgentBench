- `cpc` and `citation` in `patents_publicationinfo` are JSON arrays, not plain text. Parse with `jsonb_array_elements(col::jsonb)`, not regex/LIKE. Each `cpc` element has `code` (e.g. "H04N19/61") and `first` (bool; true = primary classification). Each `citation` element has `publication_number`. To find citing patents, join a citation element's `publication_number` against the target's own publication number — never `LIKE '%pubnum%'` on raw text.
- `patents_cpc_definition.symbol`: level 4 rows are 3-char class codes (e.g. "B33"); level 5 rows are 4-char subclass codes. Derive a patent's class/subclass from the matching-length prefix of its `cpc` code; filter `level` to the granularity asked.
- `Patents_info` is one sentence per row from many templates: an opener, an assignee phrase (verbs held by/owned by/assigned to/belonging to, or "<name> holds the ..."), and a closer with the publication number. Anchor regexes on these connector words, not `LIKE '%name%'`; sample rows before trusting a pattern. Country code is the 2-letter prefix of the publication number in the sentence.
- Assignee comparisons must be exact equality after extraction, not substring: distinct assignees can share a name prefix.
- date fields are free text (month name/abbrev, ordinal day, 4-digit year, or "None Date"); extract year/month with regex, not casting.
- For per-year aggregations per group, zero-fill missing years with `generate_series` first.
