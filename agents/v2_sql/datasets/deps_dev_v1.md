- Star/fork/other repo metrics live ONLY as free text in `deps_dev_v1_project_info."Project_Information"`, never as separate numeric columns. Extract the `owner/repo` slug from that text with a regex like `[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]*[A-Za-z0-9_-]`, lowercase it, and join to lowercased `deps_dev_v1_project_packageversion."ProjectName"`. Don't match Project_Information to ProjectName via LIKE/substring on the whole text blob.
- Fork counts appear in three mutually exclusive phrasings that together cover every row: a "count of N forks" style, a "forked N times" style, and a plain "N forks" style. Try all three (case-insensitive) before trusting one, strip thousands commas, cast to a number. Star counts and other metrics likely have similarly varied phrasings worth surveying first.
- `Licenses` and `VersionInfo` columns are JSON stored as text, sometimes pretty-printed across lines. Parse as JSON rather than substring/LIKE, which can miss whitespace variants.
- One GitHub project maps to many package versions in project_packageversion. To pick "the" version for a project, rank by most recent publish time, then release ordinal, then version string, and take the top-ranked one per project.
- Join path: packageinfo(System,Name,Version) = project_packageversion(System,Name,Version); project_packageversion.ProjectName equals the slug extracted from project_info.Project_Information, not a free-text search match.
