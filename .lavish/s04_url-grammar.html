01 · the two problems, as reported

Both complaints are true, and both come from the same missing rule

"What is the URL id /1?"

It is the question's number inside its dataset: the index names every question <dataset>/<n>, so deps_dev_v1/1 is the same id the Datasets table, the Runs board, the Query page and results.jsonl all print. The path only turned its slash into a path separator.

The confusion is real, though, because the Agent tab spells the same question pancancer_atlas_2_t1: that is the trace file name on disk (traces/<dataset>_<n>_t<trial>.json), built by traceKey() in lib/api.ts, leaked into two URLs (/runs/…/traces/… and ?trial=). Nothing in the code says which spelling is the id.

"Clicking a query goes to a new URL, not the same page"

Correct. /golden/:key/:n is a sibling route of /golden in main.tsx, so React Router unmounts the list and mounts the editor as a whole page; the coverage table you were scanning is gone, and you go back to find the next question.

The Agent tab and the Runs compare already do the other thing: one page, selection in the address (?run=&trial=&node=, ?focus=&challenger=). The Golden tab just was not built to that shape. The address should still change when you pick a row, so the view is linkable and refresh and back work; what must not change is the page around it.

Note on the transcript-rag-agent writes: I read s01 (frontend review), s02 (chat-first redesign), s13 (walkthrough), s20 (ship like a studio) and s21 (workbench studio). They do not discuss URL structure at all; s02 even chose hash tabs with no router. The one transferable pattern is s21's: a per-item drawer opened from the list plus a slim sticky in-page nav, which is the shape §6 gives the Golden tab.

03 · what the research says

Four settled conventions cover both problems; none of them is exotic

The URL is part of the interface (NN/g, "URL as UI")

Nielsen's guidance, still the reference: URLs should be readable, lowercase, and hackable: a reader can chop segments off the end and land somewhere sensible. They should visualise the site structure, and they should persist: a changed address breaks bookmarks, so old ones must keep landing. People remember and share URLs; an opaque one is a small tax every time.

Applied here: /queries/deps_dev_v1/1 fails the chop test (the parent is blank) and deps_dev_v1_1_t1 is opaque; /datasets/deps_dev_v1/1 and /runs/<run>/deps_dev_v1/1/t1 pass both.

Path names the resource; query string carries options

The API-design consensus (the same rule REST guides give) is that path segments identify a resource or a hierarchy and query parameters hold optional, independent constraints with defaults: filters, sort, a selection, a view. A query parameter can be dropped and the page still means something; a path segment cannot.

Applied here: which agent version is not optional on the Agent tab, so it belongs in the path (/agent/champion); which node is selected, which run is replayed, how the compare is grouped, all have defaults, so they stay in ?.

Master-detail: the list stays, the detail opens beside or above it

The master-detail pattern (Windows, Oracle Alta, Finastra, every design system) is "a list of something and the details of the selected item, on the same page". The detail is still addressable: the selection is in the URL, so a link opens the list with that item open. Only small screens collapse it into a drill-down.

Applied here: the Golden tab is a list of 54 questions with a tool for one at a time. That is master-detail by definition; the page-per-row shape was the wrong pick.

React Router does this with a nested route and an <Outlet>

In React Router 7 (the explorer is on 7.18.3) a child route renders inside its parent through <Outlet />; the parent stays mounted while the address changes. That is precisely "same page, new URL". Dynamic segments (:key/:n) give the id; useSearchParams gives the lens. One caveat measured in this codebase: URLSearchParams percent-encodes / and :, which is why node=tool%3Aexecute_python looks the way it does today, so the lens serialiser has to be ours.

Sources are listed at the end. The React Router page fetched documents v8.4; the nested-route and Outlet behaviour it describes is unchanged from v6 and is what 7.18.3 ships.

04 · the grammar · three rules, one module

One id per thing, path for the subject, query string for the lens, and picking never leaves the page

Rule 1 · one id, the same string everywhere

Dataset deps_dev_v1. Question deps_dev_v1/1, exactly as the index and every table print it. Trial deps_dev_v1/1/t1. Run 20260921T064521Z_v0_all_haiku. Agent version champion. Submission lb:permute_eq.

In a path, the id's slashes are path separators, which is what makes the address hackable. In a query string the id is written as-is. The trace file name deps_dev_v1_1_t1.json stays on disk and is derived from the id, never shown.

Rule 2 · path names the subject, ? holds the lens

If dropping it leaves nothing to show, it is the subject and goes in the path: a dataset, a question, a run, a trial, an agent version. If dropping it falls back to a default, it is a lens and goes in the query string: node, run+trial on the Agent tab, focus/challenger/group/scope on Runs.

Never an identity in the query string, never a preference in the path.

Rule 3 · picking from a list opens the detail in place

A tab that is a tool over a list (Golden now; Runs compare and Agent already) keeps the list mounted and opens the selection above or beside it. The address still changes, through a nested route, so the view is linkable, refresh restores it and back closes it.

A thing's own page (a dataset, a question, a run, a trial) is a destination: it may replace the page, and its breadcrumb is its hackable path.

One module owns it: frontend/src/lib/url.ts

Replaces queryPath() and traceKey() in lib/api.ts and the hand-built strings in thirteen files. Roughly:

datasetPath('deps_dev_v1')            → '/datasets/deps_dev_v1'
questionPath('deps_dev_v1/1')          → '/datasets/deps_dev_v1/1'
trialId({dataset, query_id, trial})    → 'deps_dev_v1/1/t1'
trialPath(run, 'deps_dev_v1/1/t1')     → '/runs/<run>/deps_dev_v1/1/t1'
goldenPath('deps_dev_v1/1')            → '/golden/deps_dev_v1/1'
agentPath('champion', {run, trial, node})
                                       → '/agent/champion?run=…&trial=deps_dev_v1/1/t1&node=tool:execute_python'
lens(sp, patch)                        → the query string, serialised by us:
                                         '/', ':' and ',' stay readable; only '&', '=', '#', '%' and
                                         spaces are escaped (all three are legal in a query per RFC 3986)

The backend mirror is two functions next to aliases.query_id(): trial_id() and trace_file(trial_id), so the API and the run folder agree by construction.

Why the lens serialiser is ours

setSearchParams always goes through URLSearchParams.toString(), the form-encoding serialiser, which turns deps_dev_v1/1/t1 into deps_dev_v1%2F1%2Ft1 and lb:permute_eq into lb%3Apermute_eq. Reading back is fine either way (useSearchParams decodes both), so the change is write-only: navigate({ search }) with our string, one helper, no new dependency.

This is also the honest answer to "why not put the trial in the query string as it is": we can, once the serialiser stops mangling it.

09 · risks and what is deliberately left out

Two things could bite; both have a cheap guard

Parsing the old trial key

deps_dev_v1_1_t1 cannot be split on _ blindly: dataset keys contain underscores. The redirect matches the known dataset keys first, then _<n>_t<k>. That list is 12 long and already on the page. Guarded by the routing test with every dataset key.

Route order in FastAPI

/api/runs/compare is a literal route declared before /api/runs/{run_id}, which is why it works; the new /api/runs/{run}/{ds}/{n}/t{k} must be declared after it too, and t{k} must be matched as a pattern so /traces/… never falls into it. Covered by test_api.py.

Left out on purpose

Merging the trace page into the Agent replay (they show the same trial twice, at two addresses). It would condense further, but it changes what the Agent tab is, which s02 decided; raise it after the goldens exist and the replay is used for real.

Also left out

Renaming the index id itself (deps_dev_v1/1). It is the contract the API, results.jsonl, the rescore and the golden table all share, and it is readable; the problem was never the id, it was the other two spellings.
