04 · built from MLflow · experiment dataagentbench/evals on the central server

MLflow already holds four of the six sources; the round's outcome and its session traces are added

Checked today: 8 full eval runs (v0 to v7), 5 optimise runs (v3 appears twice), a trial trace per question tagged agent · query · passed · reason, and a prompt version per agent version with the champion alias. No optimise run records whether its version won. The sessions are stored as files, not as traces.

  • Rule change, as you asked. CLAUDE.md says MLflow "is linked, never read back". This plan makes one exception, dab history. The run folders stay the record: every MLflow copy is still written from them, and a parity test holds the two equal.
  • MLflow down → the round refuses to start, as dab optimise already does (platform rule zero: no local fallback).
  • Backfill, no model call: the outcomes of rounds 1–4 come from promotions.jsonl and the scorecards, and their session traces from the session files already in runs/<run>/optimise/. From then on, dab optimise logs session traces and dab promote writes each challenger's outcome.

05 · always from the champion · agents/champion = v6_sql

A round starts from the champion's run, and reads every round from that champion that lost

  • dab optimise --into v8_sql with no run uses the champion's latest full run (champion_run_id in promotions.jsonl: v6's run 20260925T015204Z). A run whose agent is not the champion is refused, with the champion named. dab crossfit passes its own run and is unaffected.
  • Failed attempts accumulate. The "last attempt" block covers every version whose challenger_of is the champion and that lost to it: v7 now. If v8 also loses, v9 reads both v7 and v8. A new champion starts a new list, while the per-question history keeps every version.

06 · guards on the history · the existing guard and G1–G4 still check every write

The history is input only; it never shows an answer and never enters an agent's prompt

idrulewhy
H1A past answer is shown only as pass or fail, never as textfor a question with no golden (agnews/4, crmarenapro/7), an answer that passed is the gold answer
H2The statement that last passed is shown: the agent's own SQL, not a goldenit is the most direct evidence of what worked; anything written from it still passes the literal guard, G1 and the G2 audit
H3A flip with no change to the question's dataset notes or its break-step section is labelled "no prompt change: model or run noise"one trial per version; agnews/4, crmarenapro/3 and stockmarket/4 flipped on model switches alone
H4Size caps: 1,500 characters of history per question, 600 per diff, 2,000 per session for the last-attempt blocka session that reads five questions gets at most ≈ 20,000 extra characters
H5The history goes to the optimiser only, never to the agent, the curator, or G1 (the reviewer judges the text as it stands)the same boundary goldens and ledgers already keep

10 · sources and caveats

What this rests on

  • Per-question results: trial 1 of the full run of each version (v1: 20260924T050324Z, v2: 053026Z, v3: 235835Z, v4: 235837Z, v5: 20260925T004607Z, v6: 015204Z, v7: 040220Z), from each run's scorecard.json. The same file is logged to each MLflow eval run.
  • What changed between versions: agents/<v>/datasets/*.md and the playbook sections of system.md, compared text for text. Who read what: sessions[].questions in each optimise.json.
  • "Changed together" is not "caused": with one trial per version, a statement that broke after a section changed may have broken anyway. H3 labels the flips that had no prompt change at all. Whether the history helps is what v7 against v8 measures.
  • Cost: the subscription's notional dollars for Opus 5.5 at medium, from round 4 ($4.39 optimiser, $5.15 run, $1.24 reader).
