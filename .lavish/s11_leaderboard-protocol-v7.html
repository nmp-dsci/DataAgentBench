Go train v7 on all 54

It is the leaderboard's norm and inside its rules (disclosed as Tuned ✓). The optimiser gets 16 SQL failures and 8 answer failures to learn from instead of 4 and 2, including the no-golden agnews and crmarenapro/7 answers it has never read. Held-out answers rising +5 of 16 says the playbook teaches more than the questions it read.

No-go dropping the out-of-sample score

After training on the 54, a score on the 54 is in-sample. Our SQL rose five times faster in-sample than out (+30 vs +6 points), so an in-sample number alone cannot tell a round that learned from one that memorised, and the guard only catches literal copies. Cross-fitting keeps that measurement at about $12 a round. Decided otherwise (D38 B): v7's 54 score is read as in-sample.

04 · cross-fitting · the holdout's job without wasting questions

Not run for v7 (D38 B): kept here as the way to measure generalisation if a later round needs it

Folds split the 49 questions with a golden by dataset, so each fold holds some of every dataset with three or more questions; the 5 without a golden (agnews 1–4, crmarenapro/7) are spread the same way and scored on answers only. Cross-fitting measures the procedure (learn from failures), not v7's exact text: the standard caveat, and the reason the fold prompts are never promoted.

07 · ideas from how the leaders build · mapped to the ledger's steps

They all check before they answer; the SQL-first design can do that more cheaply than anyone, because a statement can be re-run

I1 · Verify before submit

Sentinel verify_step · LabRat join verification · Spacedock verify stage

A check_sql tool: runs the draft statement and reports row count, duplicate keys, join fan-out, null share, and whether the row count matches "top N". The agent fixes before submit_answer.

keysshape · 4 of v6's 16

I2 · Profile the text columns

Permute Core evidence layer + semantic_probe · LabRat Cartographer

A deterministic profile per text column (its phrasing templates, value vocabulary, formats) built by dab context build, retrieved by a profile_column tool. It is code, never sees a question, so it is legitimate by construction.

parse · 5sources · 5

I3 · Blind second solver

Sarvam Code · Spacedock re-derivation

Write a second statement without seeing the first; if the two results differ, reconcile before submitting. It targets the leaderboard's five-trial metric's hidden cost: questions that pass in some trials and fail in others.

consistency≈ 2× tokens

I4 · Answer-shape gate

LabRat answer-shape gate · Alkera answer-delivery contract

A deterministic check of the final answer against the question's asked shape (one value vs a list, the columns it names, units) with one presentation-only retry.

shapedecision

I5 · A classification path for agnews

Scout's classification tools · LabRat embedding classification

SQL cannot classify article text, and no agnews question has a golden. A classify step in derived mode would break "one SQL statement", for at most 2–4 points. Decide separately.

changes the design

I6 · More effort

Camber high · Permute Core max · LabRat high

We run Opus at medium. Effort is a one-line change (dab version-model-style) and a clean experiment after v7, not with it.

all stepscost

Recommendation: keep v7 a prompt-only round, so its effect is measurable, and bring I2 and I1 as the next two challengers, one at a time. None of the leaders publish a step-level diagnosis like the ledger; it is what lets the optimiser target a step.

10 · sources and caveats

What this rests on, and what would change it

  • Leaderboard facts: data/upstream/README.md and SUBMISSION_RUBRIC.md at the ingested commit 0290945; the descriptions of PRs #95, #96, #92, #73, #85, #70, #75, #104, #67, #84, #63 as their authors wrote them. We have not read their traces.

  • Comparability: our agent reads a Postgres copy of the sanctioned stores (as Permute Core reads a DuckDB copy), with the hints file; its answers are judged by the same validators, and our rescore reproduces the site (tests/test_trials.py).
  • What would change the recommendation: if the cross-fit shows out-of-sample Pass@1 far below in-sample (a gap of more than ≈ 0.05), the round is fitting; then G3 tightens, or the next gains come from tools (I1, I2) rather than prompt text.
