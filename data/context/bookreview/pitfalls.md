- `bookreview_books_info.book_id` and `bookreview_review.purchase_id` are the intended join keys per hints.txt ("fuzzy join approach"), not `title`↔`title`; no measured overlap share for this pair exists in joins.md, so do not assume it's clean without checking.
- `bookreview_books_info."title"` vs `bookreview_review."title"` overlap is measured at only 0.035 raw / 0.04 normalised / 0.2727 digits-only (joins.md) — this pair is not a usable join key despite matching column names.
- `bookreview_books_info.book_id` values carry a `bookid_` prefix (e.g. `bookid_1`) and `bookreview_review.purchase_id` values carry a `purchaseid_` prefix (e.g. `purchaseid_186`) — the prefixes differ, so any join needs prefix stripping/normalisation, not a raw equality.
- `bookreview_books_info.description` is documented by hints.txt as "stored as strings" despite looking like a Python list/dict; treat it as text requiring parsing, not a JSON/array type in Postgres.
- `bookreview_books_info.features` has the same list/dict-as-string issue per hints.txt; some rows contain `[]` (empty string literal, not NULL).
- `bookreview_books_info.categories` is also a string-encoded list per hints.txt (e.g. `["Books", "Literature & Fiction", "History & Criticism"]`), not a real array/JSONB column — cannot be queried with array operators directly.
- `bookreview_books_info.author` format is inconsistent: some rows are a JSON-like string with `avatar`/`name`/`about` keys (e.g. row 1: Peter Ackroyd), others are plain text like "Sandra Wilde (Editor)" or "Remington Kane (Author)   Format: Kindle Edition" — same column, two different shapes.
- `bookreview_books_info.author` has a 25.5% null rate (profile.json: null_rate 0.255) — nearly a quarter of books have no author recorded.
- `bookreview_books_info.subtitle` has a 4.5% null rate and often encodes format/edition info (e.g. "Hardcover – Import, January 1, 2004", "Kindle Edition") rather than a true subtitle.
- `bookreview_books_info.store` has a 3.5% null rate and sometimes bundles author name plus format (e.g. "Remington Kane (Author)   Format: Kindle Edition"), despite the column being named "store".
- `bookreview_books_info.price` has a 5% null rate and includes at least one value of 0.0 (row 5, "Parker & Knight") — 0.0 is a real observed value, not necessarily a data-entry placeholder, but worth checking before treating it as "free."
- `bookreview_review.review_time` is stored as character varying (text), not a native date/timestamp type — any date filtering/casting must parse the text format `YYYY-MM-DD HH:MI:SS` (e.g. `2012-11-24 18:52:00`); no timezone is indicated.
- `bookreview_review.rating` is bigint in Postgres (integer 1–5) even though description.txt calls it "float ... 1.0-5.0 scale" — the stored representation does not match the description's stated type.
- `bookreview_review.verified_purchase` is bigint (0/1) even though description.txt calls it "bool" — treat 0/1 as the literal values, not true/false.
- `bookreview_review.text` contains embedded HTML markup (e.g. `<br />` seen in sample row 1) rather than plain text, which can affect substring/text matching.
- `bookreview_books_info.details` is a single free-text blob per book packing publisher, format, page count, and ISBN-10/13 together (per sample and hints.txt) — extracting any one fact (e.g. ISBN) requires text parsing, not a dedicated column.
- `bookreview_books_info.book_id` has 200 distinct values for 200 rows (profile.json) — appears unique, but this is not independently cross-checked against `purchase_id` uniqueness claims beyond the profile's distinct count.
- `bookreview_review.purchase_id` has 200 distinct values across 1,833 review rows (profile.json) — confirms `purchase_id` is not unique per review row; many reviews share the same `purchase_id` (i.e., repeat per book), so joins to `books_info` will fan out.
- `bookreview_review.title` (review title) and `bookreview_books_info.title` (book title) are two different columns with the same name across tables — do not conflate "title" meaning book title vs. review title.
